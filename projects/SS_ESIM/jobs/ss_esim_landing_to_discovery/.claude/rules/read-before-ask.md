# กฎ: อ่านจาก Smart Export ก่อนถาม SA (ห้ามถามสิ่งที่ไฟล์ตอบได้)

ก่อนจะให้ SA ไปเช็กหรือยืนยันค่าอะไรใน ODI Studio ให้ทำตามลำดับนี้เสมอ:

1. **อ่านค่าจาก `input/odi_reference/*` ก่อน** — รันอ่านอย่างเดียวด้วย `python scripts/pipeline/read_smart_export.py --json` (รองรับทั้ง `.xml` และ `.zip` อ่านจาก zip ตรงๆ ไม่ต้องแตกไฟล์ลง repo)
   ค่าที่ต้องอ่านเอง ไม่ถาม SA: Data Server (UserName, JavaUrl, JavaDriver), Physical Schema (SchemaName, WorkSchemaName), Logical Schema, Context mapping, ชื่อ project / package / procedure ที่มีอยู่แล้ว
   - ค่าใดที่ export ไม่มี (สคริปต์รายงานใน `notes` / `fields_seen`) ให้บอกตรงๆ ว่า "ไม่มีใน export" แล้วถามเฉพาะค่านั้น — ห้ามเดา
   - **รหัสผ่านใน export ห้ามอ่าน ห้ามนำมาใช้ ห้ามถอดรหัส** (ช่องรหัสผ่านใน config เป็น null เสมอ)

2. **เทียบค่าที่อ่านได้กับ `config/config.json` และการตัดสินใจใน `status/OPEN_DECISIONS.md`**
   - ตรงกัน: ไม่ต้องถาม ให้บันทึกผลเทียบใน `knowledge/environment-facts.md`
   - ไม่ตรงกัน: รายงานเป็นตารางสั้นๆ ว่า "export บอกอะไร / decision บอกอะไร / ต่างกันตรงไหน" และ**เสนอทางแก้พร้อม [แนะนำ] 1 ข้อพร้อมเหตุผล** แล้วถามเฉพาะสิ่งที่ตัดสินใจเองไม่ได้จริงๆ

3. **ตรวจวันที่ของ export เทียบกับวันที่ของการตัดสินใจล่าสุดเสมอ** — ถ้า export เก่ากว่า decision ให้บอกตรงๆ ว่า "ค่านี้อาจเก่า" แล้วขอเฉพาะรูปหรือค่าปัจจุบัน ไม่ใช่ถามคำถามเปิดใหม่

4. **ห้ามถามซ้ำสิ่งที่ SA ตอบไปแล้วใน `status/OPEN_DECISIONS.md`** — ก่อนถามทุกครั้งให้ค้นว่ามีการตัดสินใจเรื่องนั้นแล้วหรือยัง ถ้ามี ให้ทำตามนั้นและบอกว่าทำตาม Q ข้อไหน

5. **เมื่อต้องให้ SA ลงมือ ให้ระบุให้ครบในข้อความเดียว:**
   - ทำไมต้องทำ (อ้างบรรทัด / ไฟล์ที่เป็นที่มา)
   - ทำที่ไหนใน Studio (เมนู / ชื่อ object จริงจาก export)
   - ค่าที่ควรเป็น และค่าที่ export เห็นอยู่ตอนนี้
   - ถ้า SA ไม่ต้องทำอะไร ให้บอกว่า "ไม่ต้องทำ" ไม่ต้องถามคำถามปิดท้าย

6. **ก่อนถามคำถามใดๆ ให้ตอบตัวเองก่อนว่า "ไฟล์ใน repo หรือ export ตอบได้ไหม"** — ถ้าตอบได้ ให้อ่านแล้วตอบเอง

กฎนี้ทำงานร่วมกับ `CLAUDE.md` §6.1 (ถามทีละข้อ · อธิบายชัด · มี [แนะนำ] · ถามในแชตแล้ว agent บันทึกเอง) — เมื่อจำเป็นต้องถามจริง ให้ถามตาม §6.1
