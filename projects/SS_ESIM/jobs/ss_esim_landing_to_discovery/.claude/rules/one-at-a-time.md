# กฎ: ขอ/ให้ทำ ทีละ 1 ข้อเสมอ และอธิบายให้เข้าใจง่าย

ใช้กับ **ทุกครั้งที่ agent ต้องการอะไรจากผู้ใช้** ทุก command ทุก phase ไม่ใช่แค่คำถามที่มีตัวเลือก:

- คำถาม / ตัวเลือกให้ตัดสินใจ
- ขอข้อมูล ขอไฟล์ ขอผลรัน (CSV / ภาพ) ขอค่า
- ให้ผู้ใช้ลงมือทำ (รัน SQL, ทำใน ODI Studio, ติดต่อทีมอื่น, import, ติ๊ก checklist)

## ต้องทำ

1. ให้ **ทีละ 1 ข้อ** ต่อหนึ่งข้อความ แล้ว **หยุดรอ** ผลหรือคำตอบก่อนให้ข้อถัดไป
2. ข้อที่ให้ต้องครบในตัว: ทำอะไร · ที่ไหน · ด้วย user/เครื่องมืออะไร · ผลลัพธ์ส่งกลับอย่างไร (ชื่อไฟล์ / path เต็ม)
3. ถ้ามีงานต่อเนื่องอีกหลายข้อ บอกได้แค่ว่า "หลังข้อนี้ยังมีอีก" — **ห้ามไล่รายการข้อถัดไปทั้งหมด** (ผู้ใช้ไม่ควรต้องอ่านหรือจำแผนยาว)
4. ถ้าผู้ใช้ตอบเลขสั้นๆ (เช่น "1") ให้ตีความจากข้อที่ถามล่าสุดเท่านั้น · ถ้าเลขนั้นตรงกับตัวเลือกไม่ชัด ให้ยืนยันสั้นๆ ก่อนทำ
5. ถ้ามีหลายเรื่องที่ต้องถาม ให้เรียงตามความสำคัญ ถามเรื่องเดียวก่อน (ระบุ [n/N] ได้ แต่ถามทีละข้อ)

## ห้าม

- ห้ามให้รายการขั้นตอนหลายข้อ (1, 2, 3, ...) ให้ผู้ใช้ไปทำพร้อมกัน แม้จะ "ทำพร้อมกันได้"
- ห้ามถามหลายคำถามในข้อความเดียว หรือแนบ "คำถามถัดไป" มาด้วย
- ห้ามอ้างว่าสคริปต์ "พร้อมรัน" ถ้า agent ยังไม่เคยรันกับเครื่องมือของผู้ใช้ (DBeaver / ODI Studio / Blendata) — บอกว่า "ยังไม่ได้ทดสอบ" ทุกครั้งที่ส่งสคริปต์ให้ผู้ใช้รัน

## อธิบายให้คนทั่วไปเข้าใจง่าย (ทุกคำถาม ทุกข้อที่ให้ทำ)

ผู้ใช้ไม่ควรต้องเดาว่าถามอะไร หรือทำไปเพื่ออะไร — ทุกข้อความที่ถามหรือขอให้ทำต้องมี:

1. **ประโยคเปิดบอกว่าเรื่องนี้คืออะไร ทำไมต้องตัดสินใจ/ทำตอนนี้** ด้วยภาษาธรรมดา (1–2 ประโยค) ก่อนเข้ารายละเอียด
2. **ศัพท์เทคนิคต้องมีคำอธิบายสั้นๆ ในวงเล็บครั้งแรกที่ใช้** (เช่น "checkpoint (จุดที่บอกว่าอ่านข้อมูลถึงรอบไหนแล้ว)") — ห้ามใช้ตัวย่อหรือรหัสภายใน (Q#, GAP-nn, BR-xx, K#) โดยไม่บอกว่าหมายถึงอะไร
3. **แต่ละตัวเลือกบอกผลที่ผู้ใช้จะเห็นจริง** ("ถ้าเลือกข้อนี้ จะเกิดอะไรขึ้นกับงาน") ไม่ใช่แค่ชื่อเทคนิค · ใช้ตัวอย่างสั้นๆ ถ้าช่วยให้เห็นภาพ
4. **ประโยคสั้น ตรงประเด็น** — ถ้าอ่านรอบเดียวแล้วต้องกลับมาอ่านซ้ำเพื่อทำความเข้าใจ ให้เขียนใหม่
5. รายละเอียดเชิงลึก (ชื่อตาราง ชื่อไฟล์ โค้ด) ใส่ได้ แต่ **ต่อท้าย** คำอธิบายภาษาธรรมดา ไม่ใช่แทนที่

ตัวอย่างที่ไม่ดี: "Q14: guard RUNNING=1 AND SUCCESS IS NULL fail-fast หรือ silent skip?"
ตัวอย่างที่ดี: "รอบก่อนหน้าอาจรันค้างกลางทาง ถ้ารอบใหม่เริ่มทับ ข้อมูลอาจซ้ำหรือหาย — ให้ระบบ (A) หยุดทันทีแล้วแจ้งเตือน หรือ (B) ข้ามรอบเงียบๆ ?"

## ข้อยกเว้น

- ผู้ใช้สั่งชัดเจนในแชตว่าขอทั้งแผน/ทั้งรายการ ("สรุปขั้นตอนทั้งหมด") → ให้ได้ตามที่สั่ง
- ข้อมูลที่ agent อ่านเองจากไฟล์ได้ ไม่ต้องถามผู้ใช้เลย (ดู `read-before-ask.md`)
