| L17 | field ระดับ object ต้องลอกจาก reference ห้ามอนุมานหรือประกอบเอง: `type=` อธิบาย property ฝั่ง Java (ธงอย่าง `OkExit`, `SqlIndGrp`, `IndErr` เป็น `java.lang.String` ไม่ใช่ `DbInt`) · `SqlIndGrp` เป็นคุณสมบัติของคำสั่ง ไม่ใช่ของตำแหน่งบรรทัด `OrdTrt` · field ที่ไม่ null เลยในทุกตัวอย่างของ class คือ NOT NULL · marker metadata (`SnpGrpState`/`SnpState2`) เดาไม่ได้ | type ผิดทำให้ NPE ตอน import (โผล่ที่จุดอ่านครั้งแรก ไม่ใช่ที่ field) · `SqlIndGrp` ผิดคู่เงียบ ๆ · ใส่ null ให้ field NOT NULL ได้ `ORA-01400` (เช่น `SNP_GRP_STATE.GRP_ORDER_DISP`) | เทียบ `type=` และชุด field กับ reference ทุก class ก่อนสร้าง · อ่าน `SqlIndGrp` ตามคำแรกของคำสั่ง (TRUNCATE=0, INSERT/MERGE=2) ตรงที่ reference กำกวมให้คนระบุ · ถ้าไม่มีค่าจะใส่ให้หยุดถาม · ลอก marker metadata ทุก byte (เปลี่ยนแค่ `GlobalId` ใหม่กับ `IProject`) |
| L18 | Smart Import จับคู่ object ด้วย `GlobalId` ถ้าสุ่ม GlobalId ใหม่ทุกครั้งที่สร้าง จะถูกมองเป็น object ใหม่ | import package ที่สร้างใหม่แล้วได้ object ซ้ำอีกชุดวางข้างของเก่าที่พัง | ถ้าจะ import ทับของเดิมให้ตรึง GlobalId ไว้ในแผนการสร้าง · โปรเจกต์ใหม่จริงจึงสุ่มใหม่ (เสริม L2 เรื่อง Merge ไม่อัปเดต) |
| L19 | `RefObjFQName` ไม่ได้แยก segment ด้วยจุด ตัวบอกขอบเขตคือ `RefObjFQNameLengths` (ชื่อที่มีจุดอยู่ข้างในจึงแยกผิดทันที) | cross-reference ผูกผิด object | สร้าง FQName และ lengths จากรายการ segment เดียวกัน ห้ามสร้างจากสตริงที่ต่อแล้ว · ตรวจ: ผลรวม lengths + (จำนวน segment - 1) = ความยาว FQName |
| L20 | ระดับข้อความของไฟล์ XML: SQL ห่อด้วย `<![CDATA[...]]>` ถ้ามี `]]>` ในเนื้อ SQL จะปิด section ก่อนเวลา · XML ห้าม `--` ในคอมเมนต์ · ไฟล์ประกาศ ISO-8859-1 แต่ตัวเขียนไฟล์ที่ไม่ระวังจะ escape อักขระอื่นเป็น `&#...;` ซึ่งไม่ถูกตีความใน CDATA | parse XML ไม่ผ่าน หรือ error ของ ODI ที่อ่านไม่รู้เรื่อง · ภาษาไทยใน SQL (รวม string literal) กลายเป็น `&#3605;...` แล้ว `WHERE status = '...'` ไม่ match อะไรเลย | ตรวจจำนวน `<![CDATA[` เท่ากับ `]]>` · ไม่ใส่คอมเมนต์ XML · ให้ SQL รวมคอมเมนต์อยู่ในชุด ISO-8859-1 (หลีกเลี่ยง ไม่ใช่หาทาง escape) และตรวจว่าไม่มีไบต์เกิน 0x7F กับ `&#` ในไฟล์ |
| L21 | ธรรมเนียมและสถาปัตยกรรมต้องมาจาก reference/package จริงของ repository ปลายทางเท่านั้น: ค่าธงที่ hardcode จาก repository เดียว (`FirstUser`, `TrtType`, `ExeChannel`, `keyVect`, ชื่อ user) ผิดที่อื่น และ "field นี้ null ทุกก้อน" คือคำตอบ ไม่ใช่ช่องว่าง · การเลือก Mapping แทน Procedure โดยไม่ดูว่าทีมใช้แบบไหน | object ถือธรรมเนียมของ repository อื่นเงียบ ๆ (เช่น `FirstUser` ใส่ทั้งที่ export จริงเว้น null) · เสียเวลาหลายสัปดาห์กับ `SnpMapComp`/`SnpMapAttr` และ NPE ใน Studio ทั้งที่ทีมใช้ Procedure ธรรมดา | อ่านทุกค่าจาก reference ที่ถืออยู่ ลอก `<Admin>`/`<Encryption>` ไม่ประกอบเอง · ถ้าต้องใช้ค่าจากที่อื่นให้บอกผู้ใช้ว่าใช้ค่าอะไรและทำไม · default เป็น Procedure-based (งานที่เต็มด้วย correlated subquery/window function อยู่ในข้อยกเว้นของ Oracle เองด้วย) ยืนยัน convention กับ package จริงของทีมก่อน |
| L22 | ของที่ import ผ่านแล้วไม่ทำอะไร ไม่มี ODI error บอก: ชื่อ Variable พิมพ์ผิดใน `#CODE.V_X` (แทนค่าว่างตอนรัน) · Procedure/Variable ชื่อซ้ำ (step ผูกกับตัวหลัง) · `ProjectCode` มีจุดหรือช่องว่าง (bind ไม่ resolve) · Procedure ที่ไม่อยู่ใน step ไหน · บรรทัดคำสั่งที่ไฟล์ `.sql` ว่างหรือมีแต่คอมเมนต์ | pipeline มีรูเงียบ ๆ หรือ step ผ่านโดยไม่ทำงาน ตัวเลขผิดโดยไม่มีใครโยงกลับมา | ตรวจก่อนส่ง: ชื่อหลัง `#<ProjectCode>.` เป็น Variable ที่ประกาศจริง · ชื่อไม่ซ้ำ · ProjectCode ไม่มีจุด/ช่องว่าง · ทุก Procedure อยู่ใน step chain · ทุกไฟล์ `.sql` มีเนื้อ SQL จริง (ถ้าตั้งใจให้ไม่ทำอะไรต้องบันทึกเป็นการตัดสินใจ) |
