# กฎของทีม — Migration Workspace (ใช้กับทุกงานใน workspace นี้)

> ไฟล์นี้อยู่ที่ `kit/CLAUDE.kit.md` ของ workspace และถูก import จาก CLAUDE.md ของทุกงาน · แก้ผ่าน PR ของ kit เท่านั้น
> ถ้าขัดกับกฎส่วนกลางของ kit: กฎในไฟล์นี้ชนะเฉพาะเรื่องทีม / GitHub / สถานะ / **ใครเป็นคนรัน query (AI กับฐานข้อมูล)** · OPEN_DECISIONS / GATES ของงานชนะทุกอย่าง

## กติกาสำคัญ 5 ข้อ

1. **1 งาน = 1 โฟลเดอร์ = 1 แชท = 1 branch** (`job/<PROJECT>/<job>/R<nn>`) · 1 PR = 1 งาน · ห้ามแก้ไฟล์ของงานอื่นจากแชทนี้
2. **จบขั้นต้อง `/update-status` แล้ว push** — กล่องสถานะต้องขึ้นบนจอทุกครั้ง
3. **ห้าม import โดยไม่ผ่าน `import-lock`** (ใบงานปักหมุด "ODI_DEV กำลังใช้งาน") และ `import-unlock` เมื่อเสร็จ
4. **✅ มาจากผู้อนุมัติเท่านั้น** — ทาง PR (`/approve Q14 B`) หรือผู้อนุมัติตอบในแชทแล้ว commit จากบัญชีตัวเอง · รูปแบบบรรทัด `✅ SA <YYYY-MM-DD> @<github-login>` · AI / เจ้าของงานติ๊กแทน = CI ไม่ผ่าน
5. **AI จะเขียนขึ้น GitHub หรือรันคำสั่งบนฐานข้อมูล ต้องได้รับอนุญาตก่อนทุกครั้ง** (รายละเอียดด้านล่าง · คนเลือก "ฉันรันเอง" ได้เสมอ)

## สถานะบนจอ (ไม่ต้องเปิดไฟล์เอง)

- จบขั้นไหนก็ตาม: รัน `python scripts/ws/job_status.py --box` แล้วแสดงกล่องสถานะ **ท้ายข้อความทุกครั้ง** ตามที่สคริปต์พิมพ์ — ห้ามแต่งตัวเลขเอง
- `/status` = ทุกขั้นของงานนี้ (16 ขั้น ✓ ▶ ⏳ ○ ⛔) · `/status list` = งานของฉันพร้อมเลขให้เลือก · `/status all` = ทั้งทีม
- ขั้นที่คนทำนอกแชท (รัน DDL · Smart Import · go-live) นับว่าเสร็จเมื่อมีหลักฐานเท่านั้น: DDL → แถว `DDL` ใน `status/DEPLOY_LOG.md` พร้อมผล SELECT ที่ยืนยัน · import → `status/IMPORT_LOG.md` (เขียนโดย import-unlock)
- ⛔ "สถานะไม่ตรง" = ไฟล์ขัดกัน → บอกผู้ใช้ว่าไฟล์ไหนขัด เสนอวิธีแก้พร้อม [แนะนำ] ไม่เดาแทน

## AI กับ GitHub (กลไก ⑤)

โหมดของงาน = `job.json` `github_mode` ถ้าตั้ง ไม่งั้นใช้ `shared/team.json` `github.mode` ของ workspace

| โหมด | อ่าน (fetch · pull · ดูใบงาน · ดูสถานะ branch ของคนอื่น) | เขียน (push · เปิดใบงาน · ใส่/เอาชื่อล็อก · comment) |
|---|---|---|
| 1 อ่านเอง-เขียนถาม | ทำได้เลย | **ถามทุกครั้ง** |
| 2 ถามทุกครั้ง | ถามทุกครั้ง | ถามทุกครั้ง |
| 3 คนทำเอง | ไม่ทำ — บอกคำสั่งให้คนรัน | ไม่ทำ — บอกคำสั่งให้คนรัน |

- การถาม: แสดงสิ่งที่จะทำแบบตรงตัวและที่ไหน เช่น "จะ push branch `job/SS_ESIM/…/R01` ขึ้น `origin` (3 commit: R01 build) · ให้ทำเลยไหม ตอบ ใช่ / ไม่ (ไม่ = ผมบอกคำสั่งให้คุณรันเอง)" แล้วรอ
- ได้ "ใช่" แล้วทำ → บันทึกใน `status/MIGRATION_STATUS.md`: "<วันเวลา> <สิ่งที่ทำ> · อนุญาตโดย <ชื่อ>"
- **ห้ามเสมอ ไม่มีโหมดไหนปลดได้:** push เข้า main · force-push · ลบ branch / ใบงาน · แก้ settings ของ repo · แก้เลขใบงาน — ถูกบล็อกด้วย hook `guard_github.py` · ห้ามหาทางอ้อม
- ห้ามใส่ `--yes` ให้ `workspace.py` แทนคน · ห้ามใช้ token / รหัสของใคร
- บังคับ 3 ชั้น: permission ของ Claude Code (ถามบนจอ) → hook `guard_github.py` → branch protection + token จำกัดสิทธิ์บน GitHub

## AI กับฐานข้อมูล (2.10.0 — กติกานี้แทน "Courier loop" ข้อ 3 และข้อห้ามรัน DDL/DML ในคู่มือของ kit)

ดูโหมดของงานก่อนทุกครั้ง: `python scripts/ws/job_status.py --modes`

- **db=human** (ทีมเลือก "คนรันทั้งหมด"): AI ไม่ต่อฐานเลย · เตรียมไฟล์แล้วบอกคน **ทีละไฟล์** ตามลำดับ (1) เปิดไฟล์ไหน อยู่ที่ไหน (2) รันเพื่ออะไร (ภาษาง่าย) (3) export เป็นรูปแบบไหน (4) วางไฟล์ที่ไหน — ใช้ `run_sql.py <เป้าหมาย> --plan` ช่วยสร้างขั้นตอน
- **db=ask / db=auto** (ทีมเลือกให้ AI เข้าฐาน): AI รันได้ **ทุกคำสั่ง** (SELECT · INSERT · UPDATE · DELETE · MERGE · TRUNCATE · CREATE · ALTER · DROP) ทุก environment ที่ตั้งไว้ — **แต่ต้องขออนุญาตก่อนทุกครั้ง** ด้วยตัวรันเดียว `scripts/runpack/run_sql.py`:
  1. `python scripts/runpack/run_sql.py <pack | ไฟล์ .sql> [--env SIT] [--only S2b] --plan` → ได้แผน (SQL ที่จะรันจริง · ฐาน · คำสั่งอันตราย) + คำถาม
  2. ถามคนในแชท **ทีละครั้ง** ด้วยข้อความ ❓ ของแผน: `1 = ให้ AI รัน` (แนะนำ) / `2 = ฉันรันเอง` — ตอบเป็นเลข · ห้ามเลือกแทนคน · บอกชื่อฐาน (DEV / SIT / PROD) ชัด ๆ
  3. คนตอบ 1 → `python scripts/runpack/run_sql.py --execute <แผน> --approved "<ชื่อคน> <วันที่>"` (Claude Code จะถามยืนยันบนจออีกชั้น)
     คำสั่งที่ลบแล้วกู้คืนไม่ได้ (DROP · TRUNCATE · DELETE / UPDATE ไม่มี WHERE · ALTER … DROP) → ให้คน **พิมพ์ชื่อตาราง** ในแชทก่อน แล้วใส่ `--confirm <ชื่อที่คนพิมพ์>` · ห้ามพิมพ์แทนคน
  4. คนตอบ 2 → `run_sql.py --human <แผน>` แล้วบอกคนทีละไฟล์ (4 ข้อด้านบน) · คนรันเสร็จ → `run_sql.py --record-human <แผน> --result "<ผลที่คนบอก>"` แล้ว AI ตรวจผลด้วย SELECT (ซึ่งก็ขออนุญาตตามโหมด)
  - **db=auto** ต่างจาก ask เฉพาะ SELECT ล้วน: รัน `run_sql.py <เป้าหมาย> --run-read` ได้เลยไม่ต้องถาม (ระบบปฏิเสธเองถ้ามีคำสั่งที่เขียน) · คำสั่งที่เขียน / แก้โครงสร้างยังถามเสมอ
- ทุกที่ที่คู่มือ / คำสั่งของ kit (`/run-pack` · `/preflight` · `/read-results` · `/gen-ddl` · `/validation` · `/compare-d2` · `/cutover` · README ของ pack) บอกให้ "คนรันใน DBeaver" หรือ "ห้าม AI รัน DDL/DML" — ในโหมด ask / auto ให้ใช้ขั้นตอน 1–4 ด้านบนแทน (คนยังเลือก "ฉันรันเอง" ได้ทุกครั้ง)
- ใส่ / ลบ mock data · รัน `output/ddl/` · seed / cleanup ของ Run Pack = คำสั่งที่เขียน → ถามก่อนเสมอ · หลังรัน DDL / DML ระบบบันทึก `status/DEPLOY_LOG.md` (แถว DDL / DML) + `status/DB_RUN_LOG.md` ให้เอง
- รั้วที่ปลดไม่ได้: ห้ามเรียก `sqlplus` / `sqlcl` / เขียนโค้ดต่อฐานเอง (ต้องผ่าน `run_sql.py` เท่านั้น) · แผนที่ไฟล์ถูกแก้หลังแสดงให้คนดู = รันไม่ได้ ต้องขออนุญาตใหม่ · ไฟล์ Blendata (Spark SQL) คนรันบน Blendata · คำสั่งเขียนลงตาราง SNP_* ของ ODI ไม่รันเสมอ · อ่าน SNP_* ได้เมื่อทีมอนุญาต (`db.read_odi_log`)
- รหัสผ่านอยู่ในตัวแปรบนเครื่องเท่านั้น: `ORA_RO_PASSWORD` (อ่าน) · `ORA_RW_PASSWORD` (เขียน) · ฐานอื่นเติม `_<ENV>` เช่น `ORA_RW_PASSWORD_SIT` — ถ้า run_sql.py แจ้งว่าไม่มี ให้บอกคนตั้ง (`setx … "…"` แล้วเปิด Terminal + Claude Code ใหม่) หรือให้คนรันคำสั่งเดียวกันเองใน Terminal (ระบบถามรหัสแบบไม่แสดงบนจอ) · **ห้ามขอ / รับ / พิมพ์รหัสผ่านในแชท**
- ยังเป็นงานของคนเสมอ: Smart Import · รัน package · Generate Scenario · export Smart Export ใน ODI Studio · รันบน Blendata · ตั้งรหัสผ่าน
- 0 แถวไม่นับว่าผ่าน · error ที่ไม่รู้จัก → `/diagnose` ไม่เดา · เพิ่มฐาน / user ใหม่: `python tools/workspace.py db-connect --env SIT` · คอลัมน์ของกลาง: `python tools/workspace.py update-target --fetch-columns`

## ของกลางและเลขของงาน

- ของกลาง (Smart Export · คอลัมน์ทั้ง schema) อยู่ที่ `shared/target/` ของ workspace · ในงานเป็นสำเนา `_shared_*` (ไม่ขึ้น Git) · ห้ามแก้ — ของกลางเปลี่ยนผ่าน `workspace.py update-target` เท่านั้น
- `odi.project_code` / `odi.id_base` มาจากเลขใบงาน (90000 + เลข × 1000) — **ห้ามแก้เอง** · เลขที่ยังไม่ยืนยัน (แบบคำนวณในเครื่อง) import ไม่ได้
- หลัง G3 รุ่นของกลางถูกล็อก — ของกลางเปลี่ยน = เปิดรอบใหม่ (`workspace.py new-round --kind target`)
