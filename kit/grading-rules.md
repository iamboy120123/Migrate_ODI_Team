# grading-rules — เกรดแพ็กเกจและระดับความเร็ว (ใช้โดย scripts/checks/grade.py และ scripts/testing/perf_summary.py)

## เกรดแพ็กเกจ (ขั้น 04)

ไม่เอาคะแนนมาเฉลี่ย · ข้อเดียวไม่ผ่านก็คือไม่ผ่าน

| เกรด | ความหมาย | เงื่อนไข |
|---|---|---|
| A | ส่งได้ | G1 G2 G3 ผ่านไม่มี waiver · ก่อนส่ง P1–P6 ไม่มี FAIL · SQL ทุก task ✅ |
| B | ส่งได้ มีเงื่อนไข | มี waiver ที่อนุมัติแล้ว หรือ task ที่ 🟡 (บันทึก NO_CHANGE พร้อมเหตุผล) หรือก่อนส่งมี WARN — ใบเกรดบอกเงื่อนไขทุกข้อ |
| F | ห้ามส่ง | gate BLOCKED · ก่อนส่ง FAIL · SQL ⛔ · verify FAIL แม้ข้อเดียว — ใบเกรดบอกว่าต้องแก้อะไรที่ไหน |

## ระดับความเร็ว (ขั้น 03 ก่อนรัน · ขั้น 05.3 รันจริง)

| ระดับ | เงื่อนไข |
|---|---|
| ดี | ช้ากว่า Blendata ไม่เกิน % ใน shared/team.json และไม่มีคำเตือนรูปแบบ SQL ที่ช้า |
| ต้องดู | มีคำเตือน หรือช้าเกินเกณฑ์ แต่ยังอยู่ในกรอบเวลา batch |
| ไม่ผ่าน | เกินกรอบเวลา batch — กรณีเดียวที่ความเร็วบล็อกการส่ง |

- ไม่มีเกณฑ์ = รายงานตัวเลขดิบให้คนตัดสิน · ตัวเลขเกณฑ์อยู่ใน `shared/team.json` (perf) และ `config/perf_baseline.json` ของงาน
- ข้อมูล DEV มักน้อยกว่า PROD มาก — ทุกรายงานต้องบอกขนาดข้อมูลที่ใช้ทดสอบ
